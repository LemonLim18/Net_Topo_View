## Required Architecture

Design principle:
Network Intent -> Vendor-agnostic Playbook -> Vendor-specific Role Tasks

You MUST generate a multi-file Ansible bundle with:
- One vendor-agnostic entry playbook under `playbooks/generated/job_{run_id}/playbook.yml`
- One generated role under `roles/generated/job_{run_id}/{feature}/`
- Vendor-specific task files under:
  - `roles/generated/job_{run_id}/{feature}/tasks/main.yml`
  - `roles/generated/job_{run_id}/{feature}/tasks/cisco.yml`
  - `roles/generated/job_{run_id}/{feature}/tasks/huawei.yml`
  - `roles/generated/job_{run_id}/{feature}/tasks/juniper.yml`

## Mandatory Rules

1. The entry playbook must be vendor-agnostic.
2. Do NOT place device IPs, usernames, or passwords in generated files.
3. Use inventory groups where possible. If the intent clearly targets access switches, use `access_switches`.
4. The playbook must use variables for parameters such as VLAN IDs, names, interface values, ACL names, router IDs, and areas.
5. The playbook must use safe deployment controls:
   - `serial`
   - pre-change backup/snapshot
   - post-change verification
   - rescue/failure handling
   - check mode compatibility
6. Vendor-specific logic must live in the role task files, not in the entry playbook.
7. `tasks/main.yml` must dispatch to the correct vendor task file based on `ansible_network_os` or a normalized vendor variable.
8. Vendor task files must use the correct collection/module family:
   - Cisco IOS: `cisco.ios`. For VLANs use `cisco.ios.ios_vlans` (config list, state: merged). For interface access VLAN use `cisco.ios.ios_l2_interfaces` (config list with name, mode: access, access.vlan). Do NOT use deprecated `cisco.ios.vlan` or `cisco.ios.vlan_interfaces` (removed from the collection).
   - Huawei VRP/CloudEngine: `community.network`
   - Juniper: `junipernetworks.junos`
9. Output only supported files for the feature; all listed task files must be present, but files for non-applicable vendors may contain a safe explanatory debug task.
10. The content must be idempotent and safe for check-mode.
11. Treat the `Scoped Target Device Inventory` block as authoritative for target devices, vendor resolution, management endpoints, interfaces, roles, sites, and neighbor/link hints.
12. The entry playbook should target the correct inventory groups or hostnames derived from that scoped inventory instead of inventing generic host patterns.
13. Vendor-specific task selection must follow the resolved per-device vendor facts from the scoped inventory, even when the top-level vendor hint is empty or mixed.

## Supported Feature Guidance

- `vlan`: create or merge VLAN state and verify it exists
- `interface`: apply interface config safely and verify interface state
- `acl`: configure ACL resources safely and verify presence
- `routing`: configure simple routing resources safely and verify neighbor or route visibility
